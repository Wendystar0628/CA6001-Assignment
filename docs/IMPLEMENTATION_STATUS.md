## 实施时解决的问题

- 原筛选清单有3个位置不能形成完整24单元网格，程序按蓝图0.5m缺口规则排除，未用外推补齐。
- 4个场地全球位置未确认：保留来源项目分组、逐折列出未核实组；可通过独立严格配置排除，不将其写成已验证独立。
- XGBoost与TabPFN共享16特征，支持行整位置留一；GP源趋势按训练场地等权。
- TabPFN预处理只拟合support，query标签仅交损失；验证早停统一为CPT→episode→场地宏平均RMSE。
- Pilot、validation、test分开；不完整预算曲线不进入稳定达标与精确成本配对。这比仅对“已运行节点”描述稳定性更保守，避免短曲线与完整曲线错误配对。
- 已完成训练产物续跑时复用；每任务结果幂等替换；输入或分组变化要求新run。
- Git不含原始大包/NPZ/权重；`restore-inputs`从公开原包及固定清单重建数值，不覆盖已有数据。

`runs/tabpfn-smoke/pilot_summary.json`：真实RTX4080、TabPFN9.2.0/v2、PyTorch2.11.0+cu128。一次216行episode（120 support+96 query）发生真实参数更新，保存后重载并替换两次context；参数保持冻结。单步约0.359秒，整个验证约19.60秒，峰值已分配CUDA内存约253.61MiB。该小任务时间与显存不能外推正式全任务。
